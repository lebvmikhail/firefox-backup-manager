# Архитектура Firefox Backup Manager

Документ описывает фактическую реализацию ветки `development`. Сборка и smoke-тесты выполняются Windows CI; они используют синтетические данные и не заменяют испытание на реальном профиле Firefox и целевой пользовательской системе.

## 1. Общая схема

Приложение реализовано как одно C#-приложение Windows Forms. Один исполняемый файл используется в четырёх сценариях:

1. **Интерактивная настройка** — выбор профиля, каталога резервных копий, пароля и регистрация задачи Планировщика.
2. **Фоновое резервирование** — запускается аргументом `--silent-backup`, читает сохранённую конфигурацию и выполняет резервное копирование без графического интерфейса.
3. **Проверка архива** — проверяет формат 7z, список путей, наличие корневых файлов профиля и целостность через `7z t`, не распаковывая содержимое.
4. **Восстановление** — выбор архива, каталога назначения и пароля в интерфейсе; проверка архива и распаковка в новую отдельную папку.

Код пока сосредоточен в классе `Program`. Выделение отдельных модулей запланировано после стабилизации поведения и появления тестов.

## 2. Обнаружение профилей Firefox

Путь к `profiles.ini` определяется относительно профиля текущего интерактивного пользователя через `Environment.SpecialFolder.ApplicationData`.

Парсер построчно ищет секции `[Profile...]` и значения `Name`, `IsRelative`, `Path`. Относительные пути объединяются с каталогом `profiles.ini`, абсолютные используются напрямую. Для отбора проверяется каталог и наличие `places.sqlite` либо `logins.json`. Предусмотрен дополнительный поиск этих файлов на один уровень вниз.

Это упрощённый INI-парсер, а не полная реализация формата Firefox. Нестандартные конфигурации, несколько установок Firefox и профили в специальных расположениях требуют дополнительного тестирования.

## 3. Проверка состояния Firefox

Перед созданием архива вызывается `Process.GetProcessesByName("firefox")`.

Если найден хотя бы один процесс Firefox, резервирование отменяется. Программа не завершает процессы браузера принудительно. Проверка не ограничена выбранным пользователем или конкретным путём профиля: видимый процесс Firefox в другой пользовательской сессии тоже блокирует операцию.

Проверка выполняется до архивации и повторяется после тестирования временного архива. Это снижает риск чтения изменяемого профиля, но не создаёт атомарной блокировки запуска Firefox: браузер может стартовать сразу после последней проверки. Этот сценарий остаётся ограничением и предметом дальнейшей работы.

## 4. Работа с 7-Zip

### 4.1. Поиск архиватора

Метод `Find7Zip()` проверяет стандартные каталоги Program Files и возвращает первый существующий `7z.exe`. Если файл не найден, операция завершается ошибкой.

### 4.2. Запуск процесса

Методы `QuoteArgument()`, `BuildCommandLine()` и `RunProcess()` формируют командную строку Windows и запускают дочерний процесс без оболочки.

`RunProcess()`:
- перенаправляет stdout и stderr и асинхронно собирает вывод;
- ограничивает время ожидания;
- возвращает код завершения и диагностику;
- при превышении тайм-аута завершает дочерний процесс архиватора/утилиты, но не Firefox;
- освобождает объект процесса после выполнения.

`Run7Zip()` дополнительно проверяет, что процесс запустился и завершился с кодом 0. Любой другой код считается неуспешной операцией.

### 4.3. Создание и публикация архива

Метод `CreateBackup()` выполняет следующую последовательность:

1. Проверяет параметры и наличие каталога профиля.
2. Требует корневой `places.sqlite` или `logins.json`, чтобы не создавать архив из произвольного каталога.
3. Запрещает размещать каталог назначения внутри резервируемого профиля.
4. Проверяет существующие компоненты путей к профилю и каталогу назначения на reparse points; это закрывает обход проверки вложенности через destination junction, ведущий внутрь профиля.
5. Проверяет, что Firefox закрыт, до создания каталога назначения и файла блокировки.
6. Создаёт каталог назначения и проверяет путь повторно.
7. Перечисляет файлы профиля и считает их суммарный размер. Ошибка перечисления прерывает операцию.
8. Проверяет готовность целевого тома и ориентировочный объём свободного пространства.
9. Получает эксклюзивную файловую блокировку `.firefox-backup-manager.lock` в каталоге назначения. Сам файл блокировки остаётся в каталоге; эксклюзивная блокировка действует во время операции.
10. Повторно проверяет, что Firefox закрыт перед запуском архиватора.
8. Создаёт уникальный временный файл списка исключений кэша.
9. Запускает 7-Zip для создания временного архива с суффиксом `.partial.7z`.
10. Проверяет код завершения, наличие и ненулевой размер временного архива.
11. Запускает команду 7-Zip `t` для проверки содержимого архива.
12. Повторно проверяет, что Firefox не был запущен во время операции.
13. Перемещает временный файл в окончательное имя в том же каталоге назначения.
14. В блоке очистки удаляет незавершённый временный архив и временный файл исключений.

Окончательное имя содержит безопасную версию имени профиля, дату/время с точностью до секунд и короткий случайный идентификатор. Временный архив не считается готовой резервной копией.

Проверка `7z t` подтверждает, что 7-Zip может прочитать архив и проверить данные, но не заменяет восстановление в отдельную папку и запуск восстановленного профиля Firefox.

### 4.4. Предварительная оценка свободного места

Метод `EnsurePathHasNoReparsePoints()` отклоняет reparse points во всех существующих компонентах путей к профилю и каталогу назначения. Это не позволяет обойти лексическую проверку вложенности через destination junction, ведущий внутрь профиля. Метод `TryGetDirectorySize()` дополнительно обходит само дерево профиля вручную, считает размер обычных файлов и отклоняет reparse points (символические ссылки и junction), не переходя по ним. Ошибка перечисления или обнаруженная ссылка прерывают операцию. Перед публикацией архива обход выполняется повторно; если суммарный размер изменился, временная копия не публикуется.

Это консервативная оценка, а не точный прогноз размера сжатого архива. Реальное требование к свободному месту может отличаться. Доступность сетевых путей и съёмных устройств под `SYSTEM` требует отдельных испытаний. Профили и пути к профилю/назначению, в которых используются ссылки или junction, текущая версия намеренно не поддерживает. Каталог без корневого `places.sqlite` или `logins.json` не принимается за профиль Firefox.

### 4.5. Отдельная проверка архива

Метод `VerifyBackupArchive()` использует общую проверку списка элементов, но отключает проверку свободного места, поскольку распаковка не выполняется. Он требует архив формата 7z и корневой `places.sqlite` или `logins.json`, проверяет относительность и безопасность всех путей, затем запускает `7z t`. Пароль передаётся через stdin; временный журнал удаляется после операции. Архив остаётся неизменным.

### 4.5. Проверка и восстановление архива

Метод `RestoreBackup()` выполняет восстановление только в новую директорию внутри выбранного пользователем родительского каталога:

1. Принимает только существующий файл `.7z`.
2. Получает технический список элементов через `7z l -slt`; проверяет тип архива, относительность путей и допустимость компонентов для Windows.
3. Отклоняет абсолютные пути, `..`, альтернативные потоки NTFS, зарезервированные имена устройств, а также символические и жёсткие ссылки.
4. Проверяет архив командой `7z t` с передачей пароля через stdin.
5. Распаковывает содержимое в уникальный временный каталог в том же родительском каталоге.
6. Проверяет наличие `places.sqlite` или `logins.json`, повторно проверяет отсутствие reparse points и только затем перемещает каталог под окончательное уникальное имя.
7. При любой ошибке удаляет временный каталог без перехода по reparse points и не изменяет уже существующие данные.

Для ограничения памяти сборщик вывода дочернего процесса хранит не более 16 МиБ текста. Если технический список элементов архива превышает этот предел, восстановление прекращается безопасным отказом. Восстановление не переключает профиль Firefox автоматически и не запускает браузер.

## 5. Пароль и шифрование

Если пользователь задаёт пароль, при создании архива 7-Zip получает переключатель `-p` без значения, флаг `-mhe=on` и `-sccUTF-8`. Сам пароль передаётся отдельно через перенаправленный стандартный ввод (UTF-8), а не как аргумент командной строки. При проверке архива `7z t` запрашивает пароль для зашифрованного архива и получает его тем же способом. Для формата 7z используются AES-256 и шифрование заголовков. Если пароль пуст, архив создаётся без шифрования.

Сохранённый пароль защищается Windows DPAPI с `DataProtectionScope.LocalMachine`. Эта область связывает возможность расшифровки с данной машиной Windows, но не является аппаратной привязкой и не означает, что доступ имеет только один пользователь. Компрометация самой машины или получение достаточных локальных привилегий могут ослабить защиту.

Метод `TryDecryptPassword()` различает пустой пароль и ошибку расшифровки. Если в конфигурации сохранён зашифрованный пароль, но DPAPI не может его расшифровать, фоновый запуск прекращается. Он не переходит к созданию незашифрованного архива.

**Ограничение безопасности:** значение пароля не помещается в аргументы командной строки; приложение передаёт его 7-Zip через перенаправленный стандартный ввод в UTF-8. Это уменьшает риск случайного раскрытия секрета через список аргументов процессов, но не защищает от администратора, отладчика или вредоносной программы с достаточными локальными правами, а также от чтения памяти процесса.

## 6. Конфигурация и Планировщик Windows

Конфигурация хранится в `PrivateConfig\\config.ini`. Она содержит имя и абсолютный путь профиля, абсолютный каталог резервных копий и DPAPI-значение пароля в Base64. `TryReadBackupConfig()` ограничивает размер файла 64 КиБ, требует ровно по одному обязательному ключу, отклоняет неизвестные и повторные ключи, относительные пути, отсутствующий профиль, каталог назначения внутри профиля и некорректный Base64. Пустое значение `BackupPassword` допустимо и означает, что пользователь явно выбрал незашифрованные архивы.

Запись конфигурации выполняется через временный файл и последующую замену/перемещение, чтобы не оставлять частично записанный конфиг при обычном сбое файловой операции.

Задача `Firefox_Local_AutoBackup` регистрируется через PowerShell только если исполняемый файл расположен под стандартным каталогом `Program Files` или `Program Files (x86)`, наследующим штатные Windows ACL. Запуск из пользовательской папки вроде Downloads или Desktop блокируется. Фоновый режим дополнительно завершится кодом `8`, если EXE оказался вне Program Files. При запуске GUI приложение проверяет ранее зарегистрированную задачу и удаляет её, если XML действия указывает на EXE вне защищённого каталога.
- триггер — при старте Windows;
- исполняемый файл — текущий `Firefox_Backup_Manager.exe`;
- аргумент — `--silent-backup`;
- пользователь задачи — `SYSTEM`;
- настройки разрешают запуск и продолжение работы при питании от батареи.

DACL каталога и файла заменяется на защищённый список доступа с полным доступом только для LocalSystem и локальных Administrators; наследование от родительского каталога отключается. При первом запуске старый `config.ini` переносится в новый каталог и удаляется. Если старый файл не удаётся удалить, его ACL сначала ограничивается теми же SID, после чего запуск сообщает об ошибке.

Код проверяет exit code PowerShell и затем запрашивает задачу через `schtasks.exe /Query`. Сам факт наличия `config.ini` больше не считается доказательством, что задача зарегистрирована.

**Ограничение DPAPI LocalMachine:** любой локальный пользователь, который может прочитать DPAPI-блок, может расшифровать его. Поэтому доступ к `PrivateConfig\\config.ini` ограничен ACL для LocalSystem и локальных Administrators. Это не защищает от администратора, вредоносного ПО с повышенными привилегиями или компрометации машины.

**Ограничение контекста SYSTEM:** задача работает не в пользовательской интерактивной сессии. Проверка пути опирается на стандартные ACL Program Files и не проверяет пользовательские изменения ACL внутри этих каталогов; не изменяйте права на каталог установки, разрешая обычным пользователям запись. Доступ к пользовательскому профилю, съёмным и сетевым дискам зависит от ACL, наличия тома и учётных данных. Эти сценарии не должны считаться поддерживаемыми, пока не будут проверены на реальных конфигурациях.

## 7. Фоновый сценарий и коды завершения

Фоновый режим возвращает коды завершения:
- `0` — резервная копия создана, проверена и опубликована;
- `2` — отсутствует конфигурация;
- `3` — ошибка чтения конфигурации;
- `4` — конфигурация неполная/некорректная, путь не абсолютный или каталог профиля отсутствует;
- `5` — каталог назначения/журнал недоступен;
- `6` — не удалось расшифровать сохранённый пароль;
- `7` — резервная копия не создана или не прошла проверку.
- `8` — фоновый запуск обнаружил EXE вне защищённого каталога Program Files.

Ротация запускается только после успешного возврата из `CreateBackup()`. Если создание, проверка или публикация завершились ошибкой, старые архивы не удаляются.

## 8. Ротация

Метод `RetainOldBackups()` рассматривает только файлы с точным шаблоном имени, создаваемым приложением: `Profile_yyyy-MM-dd_HH-mm-ss_XXXXXXXX.7z`, где последние восемь символов — шестнадцатеричный идентификатор. Временная метка формируется в invariant culture. Файлы с похожим префиксом, но другим именем, не удаляются. Подходящие архивы с датой последнего изменения старше 30 дней удаляются.

Ротация вызывается только после подтверждённого создания новой копии. Ошибка удаления конкретного старого архива записывается как предупреждение и не превращает успешно созданную резервную копию в неуспешную.

В будущих версиях следует добавить минимальное число сохраняемых копий и предварительный просмотр удаления. Сейчас такой гарантии нет: при успешном новом резервировании все архивы данного профиля старше 30 дней могут быть удалены.

## 9. Логирование

Журнал `backup_log.txt` пишется в каталоге резервных копий в UTF-8. При превышении 5 МиБ журнал очищается и начинается заново. Вывод 7-Zip может добавляться в журнал.

В журнал не следует записывать пароль, DPAPI-значение или другие секреты. В будущей версии необходимо усилить обработку ошибок самого логирования: текущий метод подавляет исключения записи, поэтому при недоступном журнале диагностика может быть неполной.

## 10. Сборка

Скрипт `compile.bat` использует компилятор C# .NET Framework (`csc.exe`) из Windows и создаёт `Firefox_Backup_Manager.exe`. Для запуска приложения используется manifest с запросом административных прав. Сам процесс компиляции не требует административных прав.

Скрипт выводит SHA-256 исходного файла и бинарного результата. Контрольная сумма позволяет сравнить файлы, но не подтверждает личность автора или издателя; для проверки издателя нужна цифровая подпись.

## 11. Известные ограничения и дальнейшая работа

- Восстановление работает только с архивами `.7z`, созданными в ожидаемой структуре профиля; формат архива и элементы проверяются до распаковки.
- Приложение не восстанавливает поверх существующего профиля и не запускает Firefox автоматически.
- Передача пароля через стандартный ввод уменьшает раскрытие в списке аргументов, но не защищает от локального администратора или вредоносной программы с достаточными привилегиями.
- Проверка работающего Firefox по имени процесса не обеспечивает атомарную блокировку запуска браузера.
- CI проверяет отдельную верификацию и восстановление синтетического набора файлов, но не заменяет end-to-end тест настоящего профиля Firefox с запуском браузера.
- Профиль с reparse points не резервируется; приложение намеренно не следует по ссылкам/junction и не создаёт из них архив.
- Работа `SYSTEM` с сетевыми и съёмными накопителями требует отдельной проверки.
- Парсер `profiles.ini` остаётся упрощённым.
- Автоматические тесты и сборка Windows CI должны быть подтверждены успешными запусками workflow; наличие файла workflow само по себе не является доказательством прохождения тестов.
