# Архитектура Firefox Backup Manager

Документ описывает реализацию в ветке `development`. Он не означает, что все сценарии уже проверены на реальных системах Windows.

---

## 1. Общая схема

Приложение реализовано на C# с интерфейсом Windows Forms. Исходный код пока находится в одном файле `compiler_code.cs`; сборка выполняется локальным компилятором .NET Framework из `compile.bat`.

Поддерживаются два режима:

- **Интерактивная настройка:** выбор профиля Firefox, каталога резервных копий и необязательного пароля; создание и проверка первой копии; сохранение конфигурации; регистрация задачи автозапуска.
- **Фоновое резервирование:** запуск с аргументом `--silent-backup`; чтение конфигурации; расшифровка пароля, если он задан; создание и проверка архива; ротация старых копий.

Оба режима используют общий метод `CreateBackup`.

## 2. Обнаружение профилей

Путь к `profiles.ini` определяется относительно `ApplicationData` текущего пользователя. Парсер выполняет построчный разбор секций и обрабатывает `Name`, `Path` и `IsRelative`.

При поиске профиля проверяется наличие `places.sqlite` или `logins.json`; в отдельных случаях выполняется поиск на один уровень вложенности.

Это облегчённый парсер, а не полноценная реализация формата INI. Он не гарантирует поддержку всех вариантов Firefox, нескольких установок, нестандартных корней и переносимых профилей. Требуется отдельное тестирование.

## 3. Предварительные проверки и согласованность данных

Метод `CreateBackup`:

1. Проверяет имя профиля, исходный каталог и каталог назначения.
2. Запрещает размещать каталог резервных копий внутри самого профиля.
3. Перечисляет файлы профиля и определяет их суммарный размер. При ошибке перечисления операция отменяется.
4. Проверяет доступность целевого корня через `DriveInfo` и сравнивает свободное место с размером исходного профиля. При ошибке проверки или нехватке места операция отменяется.
5. Открывает постоянный файл `.firefox-backup-manager.lock` с `FileShare.None`. Второй процесс не сможет одновременно резервировать данные в ту же папку.
6. Проверяет наличие процессов с именем `firefox`. Если найден хотя бы один процесс, операция прекращается. Программа не вызывает `Process.Kill()` для Firefox.
7. После архивирования и тестирования повторно проверяет наличие Firefox. Если браузер запустился во время операции, временный архив не публикуется.

Проверка процессов снижает риск копирования открытого профиля, но не создаёт атомарный снимок файловой системы и не устраняет полностью гонку между последней проверкой и публикацией. Для согласованной копии Firefox должен оставаться закрытым на протяжении всей операции.

Файл блокировки остаётся в каталоге назначения. Сама блокировка удерживается открытым файловым дескриптором и автоматически снимается при завершении процесса.

## 4. Создание и проверка архива

### 4.1. Поиск 7-Zip

Проверяются стандартные каталоги Program Files и Program Files (x86). Если `7z.exe` не найден, резервирование завершается ошибкой; старые архивы не удаляются.

### 4.2. Временный файл

Архив создаётся в каталоге назначения под уникальным временным именем с окончанием `.partial.7z`. Для списка исключений создаётся отдельный временный файл со случайным именем; он удаляется после завершения операции.

Временный архив и итоговый файл находятся в одном каталоге, чтобы финальное переименование не требовало переноса между томами.

### 4.3. Аргументы 7-Zip

Для создания используется `a -t7z` и уровень компрессии `-mx5`. Временные каталоги кэша исключаются через список `-x@`.

Если пользователь задал пароль, добавляются `-p` и `-mhe=on`. Формат 7z использует AES-256 для шифрования содержимого, а `-mhe=on` включает шифрование заголовков архива.

**Ограничение:** пароль передаётся как часть аргументов командной строки процесса 7-Zip. Это может быть доступно локальным средствам инспекции процессов. Экранирование аргументов защищает корректность разбора командной строки, но не скрывает секрет. Для устранения ограничения потребуется библиотека/SDK или иной механизм, не раскрывающий пароль в командной строке.

Если пароль оставлен пустым, создаётся незашифрованный архив.

### 4.4. Проверки

После запуска 7-Zip код:

- ожидает завершения процесса (лимит — 2 часа);
- асинхронно читает стандартные потоки вывода и ошибок;
- требует код завершения `0`; предупреждение архиватора также трактуется как неуспех;
- проверяет наличие и ненулевой размер временного архива;
- запускает `7z t` для проверки целостности;
- повторно проверяет, что Firefox не запущен;
- публикует архив под окончательным уникальным именем только после успешных проверок.

При ошибке временный архив удаляется; итоговый файл не публикуется. Проверка `7z t` подтверждает читаемость контейнера, но не заменяет пробное восстановление и запуск профиля Firefox.

## 5. Ротация

Ротация запускается только после успешного создания, тестирования и публикации новой копии. Удаляются только `.7z`-файлы с префиксом безопасного имени выбранного профиля и временем последнего изменения старше 30 дней.

Если новая копия не создана или не прошла проверку, ротация не вызывается. Ошибка удаления отдельного старого файла записывается как предупреждение.

Минимальное количество сохраняемых копий пока не настраивается.

## 6. Защита пароля и DPAPI

Заданный пароль сохраняется в `config.ini` в виде Base64-представления результата `ProtectedData.Protect` с `DataProtectionScope.LocalMachine`.

`LocalMachine` означает область защиты на уровне машины Windows, а не аппаратную привязку к CPU/TPM и не защиту от администратора или компрометации этой машины.

В фоновом режиме различаются два сценария:

- пустое значение означает, что пользователь намеренно не задавал пароль;
- непустое значение, которое не удалось расшифровать, приводит к отмене резервирования. Автоматического перехода к незашифрованному архиву нет.

Пароль не записывается в журнал. Однако он пока передаётся в командной строке 7-Zip и может быть виден локальным инструментам инспекции процессов.

## 7. Планировщик Windows

Для регистрации используется Windows PowerShell и модуль ScheduledTasks:

- триггер `AtStartup`;
- учётная запись `SYSTEM`;
- параметры `AllowStartIfOnBatteries` и `DontStopIfGoingOnBatteries`;
- аргумент приложения `--silent-backup`.

Код проверяет завершение PowerShell и затем выполняет контрольный запрос наличия задачи через `schtasks.exe /Query`.

Задача запускается в системном контексте. Доступность пользовательских сетевых дисков, учётных данных NAS и съёмных носителей не гарантируется и требует отдельных испытаний.

## 8. Конфигурация и журналы

`config.ini` хранится рядом с исполняемым файлом и содержит имя профиля, путь к профилю, каталог резервирования и DPAPI-значение пароля.

Конфигурация записывается во временный файл и затем заменяется/перемещается в целевой путь. Журнал `backup_log.txt` хранится в каталоге резервных копий. При превышении 5 МБ журнал очищается. Ошибки записи журнала пока обрабатываются мягко и не всегда могут быть сообщены пользователю.

Фоновый режим возвращает ненулевые коды завершения при отсутствии/повреждении конфигурации, ошибке DPAPI и сбое резервирования.

## 9. Известные ограничения и дальнейшая работа

- Нет интерфейса восстановления профиля.
- Пароль передаётся в командной строке 7-Zip.
- Нет атомарного снимка живого профиля Firefox.
- Проверка наличия процессов не устраняет полностью гонку с запуском браузера.
- Парсер `profiles.ini` ограничен.
- Сетевые/съёмные хранилища в контексте SYSTEM ещё нуждаются в испытаниях.
- Необходимо выполнить сборку на Windows и функциональные QA-тесты.
