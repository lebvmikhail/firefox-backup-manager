# Технические детали и архитектура Firefox Backup Manager

Архитектурный анализ, разбор криптографических алгоритмов защиты DPAPI, механизмов локального подавления блокировок SQLite, PowerShell-транзакций планировщика, аргументов CLI 7-Zip, логики пре-валидации диска и ротации журналов утилиты Firefox Backup Manager.

---

## 1. Алгоритмы работы ядра программы

### 1.1. Разбор конфигурации Firefox (Парсинг `profiles.ini`)
Программа обращается к системному пути пользователя `%AppData%\Mozilla\Firefox\profiles.ini` и выполняет построчный анализ текстовой структуры INI-файла. Встроенный парсер динамически обрабатывает как абсолютные, так и относительные пути (`IsRelative=1`), собирая валидную цепочку пути до конечной корневой директории профиля браузера.

Чтобы исключить добавление в пулы резервного копирования пустых или поврежденных профилей, утилита выполняет принудительную валидацию метаданных:
* Проверяет физическое наличие ключевого файла `places.sqlite` (база данных истории и закладок).
* Проверяет наличие файла `logins.json` (зашифрованная база учетных данных и паролей пользователя).
* Если указанные маркеры не найдены непосредственно в корневом каталоге, алгоритм осуществляет обход дочерних поддиректорий на один уровень вглубь, проверяя наличие признаков СУБД SQLite.

### 1.2. Механизм подавления монопольных блокировок
Базы данных пользовательского профиля Firefox функционируют под управлением встраиваемой СУБД SQLite. Во время активной сессии браузера операционная система накладывает монопольную блокировку на эти файлы.

Для предотвращения порчи бэкапа и обхода ошибок отказа в доступе фоновый движок утилиты перед инициализацией архивации выполняет зачистку дескрипторов:
* Вызывает системный метод `Process.GetProcessesByName("firefox")`.
* Завершает обнаруженные активные процессы браузера с помощью метода `Kill()`.
* Ожидает полного освобождения дескрипторов ввода-вывода в течение 3000 мс через вызов функции `WaitForExit()`.

### 1.3. Криптографическая защита учетных данных (DPAPI)
Для предотвращения компрометации сохраненного мастер-пароля архива программа задействует криптографический компонент Windows — **Data Protection API (DPAPI)** через нативный класс среды .NET `ProtectedData`:
* Алгоритм симметричного шифрования привязывается к уникальному аппаратному ключу конкретной локальной машины (`DataProtectionScope.LocalMachine`).
* Сгенерированный зашифрованный байтовый массив кодируется в строку формата `Base64` и помещается в конфигурационный файл `config.ini`.
* Прямой перенос файла конфигурации `config.ini` на сторонний компьютер не позволит дешифровать пароль — доступ к ключу аппаратно заблокирован подсистемой DPAPI для других систем.

### 1.4. Интеграция с подсистемами Windows и регистрация задач
Процедура автоматизации и регистрации автозапуска выполняется в обход классической консольной утилиты `schtasks.exe` во избежание сбоев парсинга аргументов. Программа скрытно вызывает оболочку **PowerShell** и производит регистрацию задачи одной транзакцией:
1. Вызывается командлет `New-ScheduledTaskAction` для привязки исполняемого файла с ключом командной строки `--silent-backup`.
2. Инициализируется триггер автоматического запуска при старте операционной системы через вызов `New-ScheduledTaskTrigger -AtStartup`.
3. Через командлет конфигурации настроек `New-ScheduledTaskSettingsSet` передаются параметры энергонезависимости: `-AllowStartIfOnBatteries` и `-DontStopIfGoingOnBatteries`.
4. Команда `Register-ScheduledTask` регистрирует созданную задачу под учетной записью системного приоритета `SYSTEM`. Это позволяет планировщику игнорировать текущий тип питания ноутбука (сеть или аккумулятор) и стабильно выполнять резервное копирование при каждом включении ПК.

### 1.5. Параметры шифрования и аргументы CLI 7-Zip
Утилита осуществляет сборку бэкапа в криптостойкий формат `.7z`. В командную строку скрытого запуска архиватора передаются следующие аргументы CLI:
* `a -t7z` — добавление файлов в архив нативного формата 7z.
* `-mx5` — установка оптимального уровня компрессии (Normal Compression), обеспечивающего баланс между скоростью работы и размером результирующего файла.
* `-mhe=on` — шифрование оглавления (заголовков) архива. Данный флаг скрывает внутреннюю структуру каталогов и имена файлов внутри бэкапа до момента ввода пароля. Криптографический алгоритм AES-256 применяется к контейнеру автоматически при установке аргумента `-p` (пароль).
* `-x@` — передача списка исключений для отсечения временного кэша браузера (`cache2`, `startupCache`, `jumpListCache`, `thumbnails`, `shader-cache`).

### 1.6. Логирование и стандартизация текстовых потоков
Для предотвращения искажения символов кириллицы во время фоновой и ручной архивации все методы вывода данных в текстовые журналы и конфигурационные файлы привязаны к международному стандарту кодирования `Encoding.UTF8`.

### 1.7. Алгоритмы контроля ресурсов и отказоустойчивости
* **Динамическая пре-валидация емкости диска**: Перед инициацией файловых потоков C# обращается к классу `DriveInfo` для получения доступного дискового пространства на целевом накопителе (`AvailableFreeSpace`). Алгоритм сопоставляет это значение с размером папки профиля, полученным через метод `GetDirectorySize`. В случае дефицита байт транзакция прерывается на ранней стадии до вызова архиватора.
* **Потоковая ротация журналов**: Метод `AppendLogWithRotation` при каждом вызове проверяет размер файла через `FileInfo`. Если физический размер `backup_log.txt` на диске превышает `5 * 1024 * 1024` байт (5 МБ), файл перезаписывается с нуля.
* **Ротация архивов**: При регулярном фоновом запуске утилита сканирует целевую директорию и удаляет архивы текущего профиля старше 30 дней (`CreationTime < DateTime.Now.AddDays(-30)`).

### 1.8. Контрольные точки безопасности (Верификация хэш-сумм)
Для контроля целостности исходного кода и скомпилированного бинарного файла в скрипт сборки `compile.bat` интегрирована автоматическая верификация криптографических хэшей. Скрипт вызывает утилиту `certutil -hashfile` по стандарту SHA-256, фильтрует служебные строки через цикл `for /f` и команду `more +1` и выводит в консоль цифровой отпечаток файлов.

## 2. Приёмо-сдаточный тест (QA)

1. **Проверка парсера профилей**: Модифицировать файл `profiles.ini`, добавив пустой профиль без баз данных SQLite. Запустить утилиту и убедиться, что мастер настройки корректно обрабатывает ветку.
2. **Тестирование DPAPI-изоляции**: Сформировать файл конфигурации `config.ini` с зашифрованным паролем. Перенести его на другой ПК или виртуальную машину, запустить утилиту. Убедиться, что подсистема блокирует чтение ключа AES-256 на другом оборудовании.
3. **Верификация PowerShell-триггеров**: После настройки автобэкапа открыть утилиту `taskschd.msc`, зайти в свойства созданной задачи `Firefox_Local_AutoBackup` и на вкладке «Условия» убедиться, что снята галочка «Запускать только при питании от сети».
4. **Проверка скрытия оглавления архива**: Попробовать открыть созданный резервный файл бэкапа `.7z` через архиватор без ввода пароля. Утилита должна запросить пароль до вывода списка файлов.
5. **Контроль пре-валидации накопителя**: Смоделировать ситуацию нехватки свободного места на целевом диске. Убедиться, что проверка `DriveInfo` корректно прерывает выполнение до запуска 7-Zip.
