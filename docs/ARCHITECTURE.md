# Архитектура Firefox Backup Manager

Документ описывает реализацию ветки `development`. Windows CI использует синтетические данные и не заменяет испытание на настоящем профиле Firefox и целевой пользовательской системе.

## 1. Общая схема

Приложение реализовано как одно C#-приложение Windows Forms. Один исполняемый файл используется в четырёх сценариях:

1. **Интерактивная настройка** — выбор профиля, каталога резервных копий, пароля и регистрация задачи Планировщика.
2. **Фоновое резервирование** — аргумент `--silent-backup`; процесс читает пользовательскую конфигурацию и выполняет резервное копирование без графического интерфейса.
3. **Проверка архива** — проверяет формат 7z, список путей, наличие корневых файлов профиля и целостность через `7z t`, не распаковывая содержимое.
4. **Восстановление** — выбор архива, каталога назначения и пароля в интерфейсе; проверка архива и распаковка в новую отдельную папку.

Обычный запуск приложения использует манифест `asInvoker`: UAC elevation не запрашивается. Код пока сосредоточен в классе `Program`; разделение на модули отложено до стабилизации поведения.

## 2. Обнаружение профилей Firefox

Путь к `profiles.ini` определяется относительно профиля текущего интерактивного пользователя через `Environment.SpecialFolder.ApplicationData`.

Парсер построчно ищет секции `[Profile...]` и значения `Name`, `IsRelative`, `Path`. Относительные пути объединяются с каталогом `profiles.ini`, абсолютные используются напрямую. Для отбора проверяется каталог и наличие `places.sqlite` либо `logins.json`. Предусмотрен дополнительный поиск этих файлов на один уровень вниз.

Это упрощённый INI-парсер, а не полная реализация формата Firefox. Нестандартные конфигурации, несколько установок Firefox и профили в специальных расположениях требуют дополнительного тестирования.

## 3. Проверка состояния Firefox

Перед созданием архива вызывается `Process.GetProcessesByName("firefox")`.

Если найден хотя бы один процесс Firefox, резервирование отменяется. Программа не завершает процессы браузера принудительно. Проверка не ограничена выбранным пользователем или конкретным путём профиля: видимый процесс Firefox в другой пользовательской сессии тоже блокирует операцию.

Проверка выполняется до архивации и повторяется после тестирования временного архива. Это снижает риск чтения изменяемого профиля, но не создаёт атомарной блокировки запуска Firefox: браузер может стартовать сразу после последней проверки. Этот сценарий остаётся ограничением.

## 4. Работа с 7-Zip

### 4.1. Поиск архиватора

Метод `Find7Zip()` проверяет стандартные каталоги Program Files и возвращает первый существующий `7z.exe`. Если файл не найден, операция завершается ошибкой.

### 4.2. Запуск процесса

Методы `QuoteArgument()`, `BuildCommandLine()` и `RunProcess()` формируют командную строку Windows и запускают дочерний процесс без оболочки.

`RunProcess()` перенаправляет stdout и stderr, ограничивает время ожидания, возвращает код завершения и диагностику, при тайм-ауте завершает дочерний процесс и освобождает объект процесса. Пароль архива передаётся через stdin в UTF-8, не включается в командную строку.

Для системных утилит `schtasks.exe`, `powershell.exe` и `icacls.exe` используется абсолютный путь из системного каталога Windows. Поиск исполняемых файлов с этими именами в каталоге приложения или текущем каталоге не используется.

### 4.3. Создание и публикация архива

Метод `CreateBackup()` выполняет следующую последовательность:

1. Проверяет параметры и наличие каталога профиля.
2. Требует корневой `places.sqlite` или `logins.json`, чтобы не создавать архив из произвольного каталога.
3. Запрещает размещать каталог назначения внутри резервируемого профиля.
4. Проверяет существующие компоненты путей к профилю и каталогу назначения на reparse points.
5. Проверяет, что Firefox закрыт, до создания каталога назначения и файла блокировки.
6. Подготавливает каталог назначения и проверяет путь повторно.
7. Перечисляет файлы профиля и считает суммарный размер; ошибка перечисления прерывает операцию.
8. Проверяет готовность целевого тома и ориентировочный объём свободного пространства.
9. Получает эксклюзивную файловую блокировку `.firefox-backup-manager.lock` в каталоге назначения.
10. Повторно проверяет, что Firefox закрыт перед запуском архиватора.
11. Создаёт уникальный временный файл списка исключений кэша.
12. Запускает 7-Zip для создания временного архива с суффиксом `.partial.7z`.
13. Проверяет код завершения, наличие и ненулевой размер временного архива.
14. Запускает команду 7-Zip `t` для проверки содержимого архива.
15. Повторно проверяет, что Firefox не был запущен во время операции.
16. Перемещает временный файл в окончательное имя в том же каталоге назначения.
17. В блоке очистки удаляет незавершённый временный архив и временный файл исключений.

Окончательное имя содержит безопасную версию имени профиля, дату/время с точностью до секунд и короткий случайный идентификатор. Временный архив не считается готовой резервной копией.

Проверка `7z t` подтверждает, что 7-Zip может прочитать архив и проверить данные, но не заменяет восстановление в отдельную папку и запуск восстановленного профиля Firefox.

### 4.4. Предварительная оценка свободного места

Метод `EnsurePathHasNoReparsePoints()` отклоняет reparse points во всех существующих компонентах путей к профилю и каталогу назначения. Метод `TryGetDirectorySize()` вручную обходит дерево профиля, считает размер обычных файлов и отклоняет reparse points, не переходя по ним. Ошибка перечисления или обнаруженная ссылка прерывает операцию. Перед публикацией архива обход выполняется повторно; если суммарный размер изменился, временная копия не публикуется.

Это консервативная оценка, а не точный прогноз размера сжатого архива. Реальное требование к свободному месту может отличаться. Для сетевых и съёмных каталогов доступ определяется правами и подключением текущего пользователя. Профили и пути к профилю/назначению, в которых используются ссылки или junction, намеренно не поддерживаются.

### 4.5. Отдельная проверка архива

Метод `VerifyBackupArchive()` использует общую проверку списка элементов, но отключает проверку свободного места, поскольку распаковка не выполняется. Он требует архив формата 7z и корневой `places.sqlite` или `logins.json`, проверяет относительность и безопасность всех путей, затем запускает `7z t`. Пароль передаётся через stdin; архив остаётся неизменным.

### 4.6. Восстановление архива

Метод `RestoreBackup()` выполняет восстановление только в новую директорию внутри выбранного пользователем родительского каталога. До создания staging-каталога он проверяет все существующие компоненты пути к родительскому каталогу восстановления и к исходному архиву; reparse points/junction/symlink в этих путях приводят к отказу до записи журнала или распаковки:

1. Принимает только существующий файл `.7z`.
1. Проверяет, что родительский каталог восстановления и путь к исходному архиву не проходят через reparse points; затем создаёт уникальный staging-каталог внутри проверенного родителя.
2. Получает технический список элементов через `7z l -slt`; проверяет тип архива, относительность путей и допустимость компонентов для Windows.
3. Отклоняет абсолютные пути, `..`, альтернативные потоки NTFS, зарезервированные имена устройств, а также символические и жёсткие ссылки.
4. Проверяет архив командой `7z t` с передачей пароля через stdin.
5. Распаковывает содержимое в уникальный временный каталог в том же родительском каталоге.
6. Проверяет наличие `places.sqlite` или `logins.json`, повторно проверяет отсутствие reparse points и только затем перемещает каталог под окончательное уникальное имя.
7. При любой ошибке удаляет временный каталог без перехода по reparse points и не изменяет уже существующие данные.

Для ограничения памяти сборщик вывода дочернего процесса хранит не более 16 МиБ текста. Если технический список элементов архива превышает этот предел, восстановление прекращается безопасным отказом. Восстановление не переключает профиль Firefox автоматически и не запускает браузер.

## 5. Пароль и шифрование

Если пользователь задаёт пароль, при создании архива 7-Zip получает переключатель `-p` без значения, флаг `-mhe=on` и `-sccUTF-8`. Сам пароль передаётся отдельно через перенаправленный стандартный ввод (UTF-8), а не как аргумент командной строки. Для формата 7z используются AES-256 и шифрование заголовков. Если пароль пуст, архив создаётся без шифрования.

Сохранённый пароль защищается Windows DPAPI с `DataProtectionScope.CurrentUser`. Значение предназначено для расшифровки в контексте той же учётной записи Windows. При переносе конфигурации к другому пользователю или на другую систему расшифровка не гарантируется.

Конфигурация размещается в `%LOCALAPPDATA%\\Firefox Backup Manager\\PrivateConfig\\config.ini`. DACL каталога и файла отключает наследование и разрешает полный доступ SID текущего пользователя, LocalSystem и локальных Administrators. Доступ администратора остаётся доверенной границей: локальный администратор может изменить ACL или получить доступ к данным пользователя.

Метод `TryDecryptPassword()` различает пустой пароль и ошибку расшифровки. Если сохранённый пароль не удаётся расшифровать, фоновый запуск прекращается; он не переходит к созданию незашифрованного архива.

## 6. Конфигурация и Планировщик Windows

Пользовательская конфигурация хранится под `%LOCALAPPDATA%\\Firefox Backup Manager\\PrivateConfig\\config.ini`. Она содержит имя и абсолютный путь профиля, абсолютный каталог резервных копий и DPAPI-значение пароля в Base64. `TryReadBackupConfig()` ограничивает размер файла 64 КиБ, требует уникальные обязательные ключи, отклоняет неизвестные и повторные ключи, относительные пути, отсутствующий профиль, каталог назначения внутри профиля и некорректный Base64. Пустое значение `BackupPassword` допустимо и означает незашифрованный архив.

Запись конфигурации выполняется через временный файл и последующую замену/перемещение. До публикации временный файл получает отдельный защищённый ACL: текущий пользователь, LocalSystem и локальные Administrators; наследование отключается. Поэтому новый файл не полагается только на наследуемые разрешения родительского каталога.

Задача Планировщика использует уникальное для SID имя вида `Firefox_Local_AutoBackup_<SID>`. Это позволяет разным учётным записям Windows иметь отдельные задачи. Параметры задачи:

- триггер — вход пользователя в Windows (`AtLogOn`);
- действие — текущий `Firefox_Backup_Manager.exe` с аргументом `--silent-backup`;
- пользователь — текущая учётная запись Windows;
- тип входа — `InteractiveToken`: пользователь должен быть вошедшим в систему;
- уровень прав — `LeastPrivilege` / `Limited`;
- запуск и продолжение работы при питании от батареи разрешены.

Приложение использует манифест `asInvoker` и не запрашивает административные привилегии для обычного запуска или резервирования. Задача работает с теми же правами, что и вошедший пользователь, а не от имени SYSTEM. Это устраняет выполнение записи в выбранную пользователем папку с привилегиями LocalSystem.

Старые версии использовали фиксированное имя `Firefox_Local_AutoBackup` и регистрировали задачу от имени SYSTEM. Новая версия проверяет наличие такой legacy-задачи. Если она обнаружена с SYSTEM-контекстом, GUI останавливается и просит удалить старую задачу один раз из повышенного Терминала командой `schtasks /Delete /TN Firefox_Local_AutoBackup /F`. Автоматически удалять или заменять задачу SYSTEM без явного действия пользователя новая версия не пытается. Старые архивы и старый конфиг не удаляются. Пароль требуется ввести заново: DPAPI CurrentUser не переносит прежний LocalMachine blob автоматически.

Проверка XML задачи подтверждает текущий SID/имя пользователя, `InteractiveToken` и `LeastPrivilege`. Если проверка не проходит, регистрация считается неуспешной.

## 7. Фоновый сценарий и коды завершения

Фоновый режим возвращает коды завершения:

- `0` — резервная копия создана, проверена и опубликована;
- `2` — отсутствует пользовательская конфигурация;
- `4` — конфигурация неполная/некорректная или профиль недоступен;
- `5` — каталог назначения недоступен;
- `6` — не удалось расшифровать сохранённый пароль;
- `7` — резервная копия не создана или не прошла проверку;
- `8` — любой запуск обнаружил контекст SYSTEM и завершился молча до файловых операций;
- `9` — не удалось подготовить защищённый каталог пользовательской конфигурации;
- `10` — не удалось определить LocalAppData пользователя.

При обнаружении legacy SYSTEM-задачи интерактивный запуск возвращает код `11` после показа инструкции по её ручному удалению. Если задача с новым SID-именем уже существует, но не подтверждает текущего пользователя, InteractiveToken и LeastPrivilege, GUI также отказывается от настройки и возвращает код `12`.

Ротация запускается только после успешного возврата из `CreateBackup()`. Если создание, проверка или публикация завершились ошибкой, старые архивы не удаляются.

## 8. Ротация

Метод `RetainOldBackups()` рассматривает только файлы с точным шаблоном имени, создаваемым приложением: `Profile_yyyy-MM-dd_HH-mm-ss_XXXXXXXX.7z`, где последние восемь символов — шестнадцатеричный идентификатор. Файлы с похожим префиксом, но другим именем, не удаляются. Подходящие архивы с датой последнего изменения старше 30 дней удаляются.

Ротация вызывается только после подтверждённого создания новой копии. Ошибка удаления конкретного старого архива записывается как предупреждение и не превращает успешно созданную резервную копию в неуспешную.

Сейчас нет гарантии минимального количества копий: при успешном новом резервировании все архивы данного профиля старше 30 дней могут быть удалены.

## 9. Логирование

Журнал `backup_log.txt` пишется в каталоге резервных копий в UTF-8. При превышении 5 МиБ журнал очищается и начинается заново. Вывод 7-Zip может добавляться в журнал.

В журнал не следует записывать пароль, DPAPI-значение или другие секреты. Текущий метод логирования подавляет исключения записи, поэтому при недоступном журнале диагностика может быть неполной.

## 10. Сборка и уровень привилегий

Скрипт `compile.bat` использует компилятор C# .NET Framework (`csc.exe`) из Windows и создаёт `Firefox_Backup_Manager.exe`. Манифест задаёт `requestedExecutionLevel=asInvoker`: приложение не запрашивает повышение прав. Для компиляции и обычного запуска права администратора не требуются.

Скрипт выводит SHA-256 исходного файла и бинарного результата. Контрольная сумма позволяет сравнить файлы, но не подтверждает личность автора или издателя; для проверки издателя нужна цифровая подпись.

## 11. Известные ограничения и дальнейшая работа

- Проверка работающего Firefox по имени процесса не обеспечивает атомарную блокировку запуска браузера.
- Задача выполняется только после входа пользователя в Windows и не работает до входа в систему.
- Задача имеет права текущего пользователя. Она не обладает привилегиями SYSTEM; вредоносная программа, уже работающая от имени этого пользователя, находится в той же границе доверия.
- CI проверяет верификацию и восстановление синтетического набора файлов, но не заменяет end-to-end тест настоящего профиля Firefox с запуском браузера.
- Профиль с reparse points не резервируется; приложение намеренно не следует по ссылкам/junction и не создаёт из них архив.
- Доступ к сетевым и съёмным хранилищам в пользовательском контексте требует испытания на реальных конфигурациях.
- Для строгой защиты от намеренной гонки путей внутри одного и того же пользовательского SID всё ещё предпочтителен handle-based обход/открытие каталогов. Текущая модель устраняет прежнюю возможность записи через SYSTEM, но не является песочницей против вредоносного ПО с теми же правами пользователя.
- Парсер `profiles.ini` остаётся упрощённым.
- Автоматические тесты и сборка Windows CI должны быть подтверждены успешными запусками workflow; наличие файла workflow само по себе не является доказательством прохождения тестов.
