# План ручного тестирования Firefox Backup Manager

Автоматические проверки Windows CI покрывают создание архивов, отдельную проверку и восстановление синтетических архивов с паролем и без него, неверный пароль, повреждённый архив, опасные пути, очистку staging-каталога без перехода по junction, отказ при directory junction в профиле, тестовый процесс `firefox.exe`, пользовательскую задачу Планировщика с `InteractiveToken` и `LeastPrivilege`, DPAPI CurrentUser, DACL конфигурации и ротацию. Этот чек-лист предназначен для испытаний на настоящей Windows-системе и реальном тестовом профиле Firefox; он не считается выполненным только по факту зелёного CI.

Испытывать ветку `development` нужно на тестовой Windows-машине, с отдельным тестовым профилем Firefox и отдельной папкой назначения. Не проводите первые испытания на единственной копии важного профиля.

## Подготовка

- [ ] Создать или выбрать отдельный тестовый профиль Firefox.
- [ ] Добавить тестовые закладки и несколько тестовых записей, не содержащих настоящих паролей.
- [ ] Подготовить локальную папку назначения.
- [ ] Убедиться, что установлен 7-Zip.
- [ ] Скомпилировать приложение из одной ревизии исходника и сохранить SHA-256.
- [ ] Проверить, что EXE размещён в постоянном каталоге, который не будет перемещён после регистрации задачи.

## Сборка и запуск с минимальными правами

- [ ] Компилятор найден скриптом.
- [ ] Ошибок C# нет.
- [ ] Создан EXE ненулевого размера.
- [ ] Манифест EXE имеет `requestedExecutionLevel=asInvoker`.
- [ ] Обычный запуск EXE не вызывает UAC prompt.
- [ ] Настройка резервирования выполняется из обычной учётной записи без повышения прав.
- [ ] x86 и x64 проверяются отдельно, если обе архитектуры заявляются поддерживаемыми.

## Пользовательская конфигурация и DPAPI

- [ ] Конфигурация создаётся под `%LOCALAPPDATA%\\Firefox Backup Manager\\PrivateConfig\\config.ini`, а не рядом с EXE.
- [ ] DPAPI CurrentUser успешно шифрует и расшифровывает пароль в той же учётной записи Windows.
- [ ] Пароль из конфигурации не удаётся расшифровать при запуске под другой учётной записью или без пользовательского DPAPI-контекста.
- [ ] DACL каталога и файла отключает наследование и разрешает полный доступ только SID текущего пользователя, LocalSystem и локальных Administrators.
- [ ] Конфигурация с корректными уникальными ключами и абсолютными путями принимается.
- [ ] Повторяющиеся или неизвестные ключи, относительные пути, отсутствующие значения и повреждённый Base64 DPAPI-блок отклоняются.
- [ ] GUI показывает причину повреждения конфигурации и не аварийно завершается.

## Позитивные сценарии резервирования

- [ ] При закрытом Firefox настройка создаёт первую резервную копию.
- [ ] Созданный архив проходит команду `7z t`.
- [ ] При заданном пароле архив требует пароль, а имена файлов не видны до его ввода.
- [ ] Неверный пароль приводит к ошибке проверки.
- [ ] Пустой пароль создаёт незашифрованный архив и это ясно обозначено пользователю.
- [ ] Итоговое имя архива уникально при повторных запусках.
- [ ] После успешной первой копии пользовательская задача Планировщика существует.
- [ ] Задача настроена на `AtLogOn`, `InteractiveToken`, `LeastPrivilege` и текущую учётную запись.
- [ ] Задача запускает тот же EXE с аргументом `--silent-backup`.
- [ ] Задача запускается после входа этого пользователя в Windows и создаёт архив в выбранном каталоге.
- [ ] Архив и журнал создаются с правами текущей учётной записи; в операции не участвует SYSTEM.
- [ ] Логи содержат понятный итоговый статус и не содержат пароль.

## Негативные сценарии и границы привилегий

- [ ] Запущенный Firefox приводит к отмене резервирования без завершения процесса.
- [ ] Отсутствующий 7-Zip приводит к ошибке; старые архивы не удаляются.
- [ ] Недоступный каталог профиля приводит к ошибке.
- [ ] Недоступный каталог назначения приводит к ошибке.
- [ ] Каталог назначения через junction/symlink, ведущий внутрь профиля, отклоняется до создания архива.
- [ ] Каталог без корневого `places.sqlite` или `logins.json` отклоняется как не являющийся профилем Firefox.
- [ ] Недостаток места приводит к отмене операции.
- [ ] Повреждённый DPAPI CurrentUser блок приводит к отмене; открытый архив не создаётся.
- [ ] Повреждённый временный архив не публикуется под окончательным именем.
- [ ] Прерывание 7-Zip не удаляет старые проверенные копии.
- [ ] Два параллельных запуска в одной папке не выполняются одновременно.
- [ ] Повторный запуск не перезаписывает предыдущий архив.
- [ ] Ротация удаляет только старые архивы с точным шаблоном имени приложения и сохраняет произвольные пользовательские `.7z`-файлы с похожим префиксом.
- [ ] Создание/запуск задачи не требует административных прав.
- [ ] Уровень задачи всегда остаётся `LeastPrivilege`; переключение на `HighestAvailable` или SYSTEM считается ошибкой.
- [ ] Любой запуск, принудительно выполненный в контексте SYSTEM, завершается кодом `8` до чтения конфигурации и любых файловых записей; GUI показывает предупреждение, фоновый режим завершается молча.
- [ ] Разные учётные записи Windows получают разные имена задач, содержащие их SID, и не перезаписывают друг другу задачи.
- [ ] Повторный запуск настройки под одной учётной записью обновляет только её задачу.
- [ ] Если обнаружена legacy-задача `Firefox_Local_AutoBackup` от SYSTEM, GUI показывает команду ручного удаления и не пытается автоматически заменить задачу.
- [ ] Если задача с SID-именем текущего пользователя имеет SYSTEM, чужого пользователя или повышенный RunLevel, GUI отказывается её заменять и показывает команду ручного удаления.
- [ ] После ручного удаления legacy SYSTEM-задачи можно настроить новую пользовательскую задачу; старые архивы остаются на месте, пароль вводится заново.
- [ ] Ошибка регистрации задачи не показывается как успешная настройка.

## Отдельная проверка архива

- [ ] Проверить незашифрованный архив кнопкой «Проверить архив».
- [ ] Проверить зашифрованный архив с верным паролем.
- [ ] Убедиться, что неверный пароль и повреждённый архив дают отказ.
- [ ] Убедиться, что проверка не изменяет файл архива (сравнить SHA-256 до и после).

## Восстановление

- [ ] Через кнопку «Восстановить архив в отдельную папку» восстановить незашифрованный архив.
- [ ] Повторить восстановление для архива с паролем, включая пароль с пробелами и Unicode.
- [ ] Проверить отказ при неверном пароле и повреждённом архиве.
- [ ] Убедиться, что при ошибке временная папка удаляется и существующие файлы не изменяются.
- [ ] Убедиться, что восстановление не перезаписывает существующую папку и не меняет исходный профиль.
- [ ] Проверить восстановленный профиль на наличие основных файлов профиля.
- [ ] Подключить тестовую копию через менеджер профилей Firefox.
- [ ] Запустить Firefox с тестовым профилем.
- [ ] Проверить тестовые закладки и другие контрольные данные.
- [ ] Убедиться, что журнал `restore_log.txt` не содержит пароль.

## Планировщик и пользовательские среды

- [ ] Проверить запуск задачи после реального выхода из Windows и повторного входа пользователя.
- [ ] Убедиться, что задача не запускается до интерактивного входа пользователя.
- [ ] Проверить доступность локального внешнего диска после входа.
- [ ] Проверить сетевой UNC-путь под той же учётной записью и подтвердить доступ после установления сетевого соединения.
- [ ] Проверить поведение после смены пароля пользователя и после сброса/восстановления профиля Windows.
- [ ] Проверить, что задача другого пользователя не отображается как задача текущего пользователя и не изменяется при настройке.

## Ограничения

- Проверка только команды `7z t` — это не end-to-end тест восстановления.
- Пользовательская задача работает только после входа в Windows и пропускает резервирование, если Firefox открыт.
- Модель запуска исключает повышенные привилегии SYSTEM, но не изолирует приложение от другого вредоносного процесса, который уже работает с правами того же пользователя.
- Перед выпуском стабильной версии необходимо повторить тесты на каждой заявленной поддерживаемой версии Windows.
