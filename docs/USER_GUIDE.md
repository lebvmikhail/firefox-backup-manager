# Руководство пользователя Firefox Backup Manager

Это руководство описывает текущую ветку `development`. Она находится в разработке и пока не должна использоваться как единственная защита важных данных без независимой резервной копии и собственного теста восстановления.

---

## 1. Требования

- Windows с компонентами .NET Framework, необходимыми для запуска приложения.
- Установленный 7-Zip в одном из стандартных каталогов Program Files.
- Права администратора для обычной настройки и регистрации пользовательской задачи не требуются.
- Достаточно свободного места в каталоге назначения.
- Профиль Firefox должен быть обычным каталогом с корневым `places.sqlite` или `logins.json`.
- В самом профиле и компонентах пути к профилю/каталогу резервных копий не должно быть символических ссылок или junction. При их обнаружении резервирование будет отменено.

Точный перечень поддерживаемых версий Windows/.NET будет уточнён после испытаний на чистых системах.

## 2. Сборка

1. Скачайте `compile.bat` и `compiler_code.cs` из одной и той же ревизии.
2. Поместите оба файла в один каталог.
3. Запустите `compile.bat`. Для компиляции и обычного запуска приложения права администратора не требуются.
4. Убедитесь, что компилятор завершился без ошибок и создан `Firefox_Backup_Manager.exe`.
5. Сохраните выведенные SHA-256 исходника и EXE, чтобы сравнить их при необходимости.

SHA-256 — контрольная сумма файла, а не цифровая подпись и не самостоятельное доказательство того, кто выпустил программу.

## 3. Первоначальная настройка

1. Закройте Firefox перед началом настройки. Программа не будет завершать его принудительно.
2. Поместите `Firefox_Backup_Manager.exe` в постоянный каталог, доступный вашей учётной записи. После регистрации задачи не перемещайте и не переименовывайте EXE. Для пользовательской установки удобно использовать отдельную папку внутри профиля пользователя; установка в Program Files также допустима.
3. Запустите EXE обычным способом. Запуск от имени администратора не требуется.
4. Нажмите «Включить / Настроить авто-бэкап».
5. Выберите обнаруженный профиль Firefox.
6. Выберите каталог хранения резервных копий, в который текущая учётная запись имеет право записи.
7. При необходимости задайте пароль архива. Пароль может быть пустым, но тогда архив останется незашифрованным.
8. Дождитесь завершения первой резервной копии и проверки архива.

Если обнаружен работающий Firefox, недостаточно места, не найден 7-Zip, не удалось создать/проверить архив или возникла ошибка DPAPI, настройка первой копии отменяется и задача автозапуска не регистрируется.

### Где хранятся настройки и пароль

Конфигурация сохраняется в:

`%LOCALAPPDATA%\\Firefox Backup Manager\\PrivateConfig\\config.ini`

Пароль защищается Windows DPAPI с областью `CurrentUser`: расшифровать его можно в контексте той же учётной записи Windows. ACL каталога и файла отдельно ограничивает доступ текущим пользователем, LocalSystem и локальными Administrators.

### Переход со старой версии, использовавшей SYSTEM

Старая версия программы регистрировала задачу `Firefox_Local_AutoBackup` от имени `SYSTEM`. Новая версия не будет автоматически заменять или удалять такую задачу.

Если при запуске обнаружена старая задача, приложение покажет предупреждение и остановит настройку. Один раз откройте Терминал или PowerShell **от имени администратора** и выполните:

```powershell
schtasks /Delete /TN Firefox_Local_AutoBackup /F
```

После этого снова запустите новую версию программы и настройте резервирование заново. Пароль нужно будет ввести повторно: новая версия использует DPAPI `CurrentUser` и не переносит автоматически старое значение, зашифрованное через `LocalMachine`. Старые архивы и прежний файл конфигурации не удаляются автоматически. Удалять старую конфигурацию вручную следует только после проверки новой настройки и сохранения нужных копий.

## 4. Как работает автоматическое резервирование

Задача запускается **при входе в Windows текущего пользователя**, для которого она была зарегистрирована. Она использует сохранённый путь профиля и каталог резервных копий.

Параметры задачи:
- имя задачи содержит SID текущего пользователя, поэтому задачи нескольких Windows-учётных записей независимы;
- учётная запись — текущий пользователь Windows;
- тип входа — `InteractiveToken`: пользователь должен быть вошедшим в систему;
- уровень прав — `LeastPrivilege` (ограниченные права);
- действие — запуск `Firefox_Backup_Manager.exe --silent-backup`.

Фоновая задача не запускается до входа пользователя и не получает привилегии SYSTEM. Она может читать профиль Firefox и писать в выбранный каталог только в пределах прав этой учётной записи.

Перед созданием архива программа проверяет конфигурацию, расшифровывает сохранённый пароль, проверяет профиль и каталог назначения, убеждается, что Firefox закрыт, и создаёт эксклюзивную блокировку каталога резервных копий.

Если Firefox работает в момент входа пользователя, резервирование отменяется. Повторная попытка произойдёт при следующем входе в эту учётную запись; автоматического фонового повтора сразу после закрытия Firefox пока нет.

**Сетевые и съёмные диски:** новая задача использует учётную запись пользователя, а не SYSTEM. Это позволяет проверять доступ к сетевым ресурсам в пользовательском контексте, но доступность сетевого подключения сразу после входа всё равно требует проверки. Для сетевых папок предпочтительнее использовать UNC-путь и убедиться, что учётная запись имеет права записи.

## 5. Где находятся резервные копии

В выбранном каталоге создаются:
- архивы `.7z` с именем, содержащим имя профиля, дату, время и уникальный идентификатор;
- журнал `backup_log.txt`;
- файл блокировки `.firefox-backup-manager.lock`.

Временные архивы имеют суффикс `.partial.7z`. Такой файл не является готовой резервной копией. После успешной проверки временный файл переименовывается в окончательный.

Архивы выбранного профиля старше 30 дней удаляются только после того, как новая копия успешно создана, прошла тест 7-Zip и опубликована. Сценарий минимального числа сохраняемых архивов ещё не реализован.

## 6. Проверка и восстановление

Перед публикацией новая резервная копия проверяется командой 7-Zip `t`. Дополнительно в главном окне есть действие **«Восстановить архив в отдельную папку»**.

### Как проверить архив без распаковки

1. Нажмите **«Проверить архив»**.
2. Выберите файл резервной копии `.7z`.
3. Введите пароль. Для незашифрованного архива оставьте поле пустым.
4. Дождитесь результата. При успехе программа сообщает, что структура и целостность архива проверены; файлы не распаковываются и исходный архив не изменяется.

Проверка требует формат 7z и корневой файл `places.sqlite` или `logins.json`. Она проверяет список элементов и безопасность путей, затем запускает `7z t`. Неверный пароль, повреждение, ссылки файловой системы и опасные пути приводят к отказу. Если список архива слишком велик для ограниченного буфера проверки, операция также завершается безопасным отказом.

### Как восстановить копию

1. Нажмите **«Восстановить архив в отдельную папку»**.
2. Выберите файл резервной копии `.7z`.
3. Выберите родительский каталог. Программа создаст внутри него новую папку с именем архива и суффиксом `_restored`; существующие папки и файлы не перезаписываются.
4. Введите пароль архива. Для незашифрованной копии оставьте поле пустым.
5. Дождитесь окончания проверки и распаковки. При успехе программа покажет полный путь к восстановленному профилю.

Перед распаковкой приложение проверяет формат архива и пути его элементов, отклоняет абсолютные пути, выход из каталога, зарезервированные имена Windows и файловые ссылки, затем выполняет `7z t`. Распаковка идёт во временный каталог. Готовая папка публикуется только после успешной распаковки и проверки наличия `places.sqlite` или `logins.json`. При неверном пароле, повреждении или ошибке временный каталог удаляется без перехода по обнаруженным файловым ссылкам; существующие данные не заменяются.

Журнал операций восстановления — `restore_log.txt` в выбранном родительском каталоге.

### Подключение профиля к Firefox

Не копируйте восстановленные файлы поверх текущего профиля. Сначала проверьте содержимое восстановленного каталога, затем подключите его через менеджер профилей Firefox. Запускайте восстановленный профиль отдельно и убедитесь, что закладки и другие контрольные данные на месте.

Автоматическое переключение действующего профиля, восстановление поверх существующей папки и запуск Firefox из программы не выполняются. Smoke-тест проверяет только синтетический набор файлов. До хранения единственной копии важных данных необходимо провести полное восстановление настоящего тестового профиля и запустить его в Firefox.

## 7. Безопасность и ограничения

- При заданном пароле формат 7z использует AES-256 и шифрование заголовков (`-mhe=on`). При пустом пароле архив не шифруется.
- DPAPI `CurrentUser` защищает сохранённый пароль в контексте текущей учётной записи Windows. При использовании другого пользователя Windows или переносе конфигурации на другую систему автоматическая расшифровка не гарантируется.
- ACL каталога `PrivateConfig` и файла `config.ini` разрешает полный доступ текущему пользователю, LocalSystem и локальным Administrators; наследование отключено. Это не защищает от администратора, который может изменить ACL, или от вредоносной программы, уже работающей от имени текущего пользователя.
- Пароль не включается в аргументы командной строки: приложение передаёт его 7-Zip через перенаправленный стандартный ввод в UTF-8. Это снижает риск раскрытия через список процессов, но не защищает от локального администратора, отладчика или вредоносной программы с достаточными правами.
- Фоновая задача имеет те же права, что и вошедший пользователь, и не использует SYSTEM. Это снимает риск записи в выбранный каталог с системными привилегиями, но не защищает данные от вредоносной программы, уже работающей с правами этого пользователя.
- Не храните единственную копию важных данных на том же физическом диске, где находится исходный профиль.
- Для важных данных используйте дополнительную независимую резервную копию на другом носителе.

## 8. Журнал и диагностика

Откройте `backup_log.txt` в каталоге назначения. Ищите записи:
- `[УСПЕХ]` — архив создан, протестирован и опубликован;
- `[ОШИБКА]` — операция не выполнена;
- `[РОТАЦИЯ]` — удалён старый архив после успешной новой копии;
- `[ПРЕДУПРЕЖДЕНИЕ]` — вспомогательная операция завершилась с проблемой.

Если резервирование не выполняется:
1. Убедитесь, что Firefox закрыт.
2. Убедитесь, что 7-Zip доступен в стандартном каталоге Program Files.
3. Проверьте доступность выбранного каталога и свободное место.
4. Проверьте журнал.
5. Если ошибка связана с DPAPI, не очищайте конфигурацию и не пытайтесь обходить шифрование созданием открытого архива: сначала разберитесь, почему секрет не расшифровывается.

## 9. Отключение автозапуска

1. Запустите приложение под той же учётной записью Windows, для которой настраивалось резервирование.
2. Нажмите «Отключить авто-бэкап и удалить конфиг».
3. Убедитесь, что программа сообщила об удалении пользовательской задачи Планировщика и конфигурации.

Архивы резервных копий при отключении не удаляются. Удаляется только конфигурация автоматического запуска; сами архивы нужно удалять вручную после проверки, что они больше не нужны.

## 10. Передача отчёта об ошибке

При сообщении об ошибке приложите:
- версию Windows;
- версию 7-Zip;
- способ хранения архива (локальный диск/USB/NAS);
- соответствующий фрагмент `backup_log.txt`.

Перед отправкой журнала убедитесь, что в нём нет личных путей или другой информации, которую вы не хотите публиковать. Не отправляйте пароль архива и содержимое `config.ini`.
