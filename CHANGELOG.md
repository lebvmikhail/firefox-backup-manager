# История изменений

Все записи относятся к ветке разработки. Выпущенные релизы будут отмечаться отдельными версиями и тегами.

- Предварительная проверка списка элементов архива, относительности и допустимости путей до распаковки.
- Восстановление через временный staging-каталог с проверкой результата и публикацией только после успеха.

- Windows CI-проверки отдельной проверки архива и восстановления с паролем и без него, неверного пароля, повреждённого архива, опасных путей, destination junction в профиль, непрофильного каталога и зарезервированных имён устройств.

### Исправлено и усилено
- Системные `schtasks.exe` и `powershell.exe` запускаются только по абсолютным путям из системного каталога Windows; поиск по каталогу приложения, текущему каталогу и `PATH` исключён.
- Проверка родительского пути каталога резервных копий выполняется до создания каталога и любых записей журнала; начальные и отказные записи в потенциально небезопасное назначение удалены.
- Добавлены smoke-проверки разрешения системных бинарников при наличии одноимённых файлов в рабочем каталоге и отказа destination junction до создания журнала.
- Разрешено пустое значение `BackupPassword` как явный выбор незашифрованных архивов; непустое значение по-прежнему проверяется как ограниченный Base64 DPAPI-блок.
- Ограничен объём сохраняемого вывода дочерних процессов; ошибка ввода/вывода не должна оставлять дочерний процесс архиватора работающим.
- Проверка ACL конфигурации теперь подтверждает отключение наследования и явные полные разрешения для LocalSystem и локальных Administrators.
- Восстановление отклоняет абсолютные пути, выход из каталога назначения, альтернативные потоки NTFS, зарезервированные имена Windows, символические и жёсткие ссылки.
- Резервирование вручную обходит профиль и отклоняет reparse points; проверяет компоненты путей к профилю и каталогу назначения, чтобы исключить обход через junction; перед публикацией повторно проверяет состав и общий размер дерева.
- Резервирование отклоняет произвольные каталоги без корневого `places.sqlite` или `logins.json`.
- Неудачное восстановление удаляет временный каталог без перехода по reparse points и не заменяет существующие пользовательские данные.

### Ограничения текущей разработки
- CI использует синтетические файлы, а не настоящий профиль Firefox; совместимость с реальным профилем и запуск восстановленного браузера ещё нужно проверить вручную.
- CI регистрирует задачу `SYSTEM`, запускает фоновый backup-процесс вручную в контексте SYSTEM и проверяет результат; запуск именно по триггеру после реальной перезагрузки целевого компьютера всё ещё требует проверки.
- Поддержка сетевых/съёмных хранилищ, настраиваемая политика хранения, минимальное число копий и отдельный режим «только проверить архив» остаются незавершёнными.
- До объявления стабильного релиза требуется пройти ручной план тестирования из `docs/TEST_PLAN.md`.
