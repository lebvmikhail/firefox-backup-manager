# История изменений

Изменения сгруппированы по выпущенным версиям. Следующие изменения будут добавляться в раздел `Unreleased`.

## Unreleased

### Политика хранения резервных копий
- После успешного резервирования сохраняются минимум три последние копии профиля независимо от возраста; архивы старше 30 дней удаляются только сверх этого минимума. При ошибке инвентаризации ротация прекращается без удаления.
- Smoke-тесты проверяют сохранение трёх последних архивов, отсутствие удаления при количестве менее трёх и сохранность пользовательских `.7z`-файлов.

### Проверки и документация
- Windows CI запускается также при push в `main`, проверяет доступность и версию 7-Zip, использует обновлённые Actions с Node.js 24 и фиксированные commit SHA.
- Руководство пользователя, архитектура и ручной план тестирования синхронизированы с опубликованной стабильной версией `v1.0.0`.

## v1.0.0 — 2026-11-25

### Добавлено
- Фоновая задача Планировщика для текущего пользователя с триггером входа в Windows, типом входа `InteractiveToken` и уровнем `LeastPrivilege`.
- Индивидуальное имя задачи на основе SID пользователя, чтобы разные учётные записи Windows не перезаписывали друг другу задачи.
- Хранение настроек в `%LOCALAPPDATA%\\Firefox Backup Manager\\PrivateConfig\\config.ini`.
- DPAPI `CurrentUser` для защиты сохранённого пароля; ACL конфигурации включает текущего пользователя, LocalSystem и локальных Administrators.
- Защитное обнаружение legacy-задачи `Firefox_Local_AutoBackup`, ранее запускавшейся от имени SYSTEM; новая версия не заменяет её автоматически.

### Исправлено и усилено
- Обычный запуск приложения переведён на манифест `asInvoker`; настройка и фоновое резервирование не запрашивают elevation.
- Устранена необходимость выполнять запись в пользовательский каталог назначения от имени SYSTEM: задача получает только права вошедшего пользователя.
- Любой режим приложения, запущенный под SYSTEM, молча завершается до показа GUI, чтения пользовательской конфигурации и любых файловых операций.
- Регистрация задачи проверяет её principal, интерактивный тип входа и ограниченный уровень прав.
- Имя задачи включает SID текущего пользователя; при обнаружении задачи с некорректным principal или уровнем прав новая версия отказывается автоматически её заменять.
- Разные Windows-пользователи получают отдельные задачи Планировщика.
- Системные `schtasks.exe` и `powershell.exe` запускаются только по абсолютным путям из системного каталога Windows; поиск в каталоге приложения, текущем каталоге и `PATH` исключён.
- Проверка родительского пути каталога резервных копий выполняется до создания каталога и любых записей журнала; начальные и отказные записи в потенциально небезопасное назначение удалены.
- Восстановление отклоняет reparse points в пути к выбранному родительскому каталогу и исходному архиву до создания staging-каталога и записи журнала.
- Атомарная запись конфигурации сначала применяет защищённый DACL к временному файлу; опубликованный `config.ini` не полагается только на наследование ACL каталога.
- Выбор профиля сохраняет имена, содержащие разделитель ` | `; удаление задачи проверяет результат через общий helper.
- Smoke-тесты покрывают junction назначения восстановления и защищённый ACL только что созданного файла конфигурации.
- Reflection-based smoke-тест выполняется через Windows PowerShell 5.1 на .NET Framework, соответствующем runtime собранного приложения; PS-скрипт сохранён с UTF-8 BOM для корректного чтения Unicode-литералов.
- Smoke-набор проверяет CurrentUser DPAPI round-trip, DACL пользовательской конфигурации, регистрацию/запуск пользовательской задачи, а также разрешение системных бинарников при наличии одноимённых файлов в рабочем каталоге.

### Ограничения и переход со старых версий
- Legacy SYSTEM-задача не удаляется автоматически. Пользователь должен один раз удалить `Firefox_Local_AutoBackup` из повышенного Терминала, затем повторить настройку. Старые архивы и старая конфигурация автоматически не удаляются; пароль потребуется ввести заново, поскольку область DPAPI изменилась с LocalMachine на CurrentUser.
- Новая задача выполняется только после интерактивного входа пользователя и пропускает резервирование, если Firefox открыт в момент запуска.
- Запуск с правами текущего пользователя устраняет прежнюю границу SYSTEM при записи в каталог назначения, но не является песочницей против вредоносного процесса с теми же правами пользователя.
- Windows CI использует синтетические файлы, а не настоящий профиль Firefox. Ручная проверка на реальной системе подтвердила создание архива, восстановление профиля и запуск восстановленного Firefox.
- Фактический запуск задачи после входа в Windows проверен на реальной системе. Сетевые/съёмные хранилища и широкая матрица версий Windows/.NET/7-Zip требуют дополнительной проверки.
- Не все дополнительные сценарии ручного плана проверены; актуальные ограничения перечислены в README и `docs/TEST_PLAN.md`.
