# Firefox Backup Manager

Небольшая Windows-утилита для резервного копирования профилей Mozilla Firefox в архивы 7-Zip.

> **Статус разработки:** ветка `development` находится на этапе проверки. Windows CI собирает приложение и проверяет создание, проверку и восстановление синтетических архивов. Эти проверки не заменяют испытание на настоящем профиле Firefox и реальное восстановление с последующим запуском Firefox. Не используйте эту ветку как единственную систему защиты важных данных.

## Возможности текущей development-версии

- Обнаружение профилей Firefox через пользовательский `profiles.ini`.
- Создание архивов формата `.7z`; при заданном пароле используется AES-256 и шифрование заголовков (`-mhe=on`).
- Хранение конфигурации в `%LOCALAPPDATA%\\Firefox Backup Manager\\PrivateConfig\\config.ini`.
- Защита пароля Windows DPAPI с `DataProtectionScope.CurrentUser`; ACL конфигурации разрешает полный доступ текущему пользователю, LocalSystem и локальным Administrators.
- Строгая проверка `config.ini`: обязательные уникальные ключи, абсолютные пути, существующий профиль и корректный Base64 DPAPI-блок, если пароль задан; пустое значение означает намеренно незашифрованный архив.
- Передача пароля 7-Zip через перенаправленный стандартный ввод UTF-8, без помещения значения пароля в аргументы командной строки.
- Создание архива под временным именем, проверка командой `7z t` и публикация под окончательным именем только после успешных проверок.
- Отдельная проверка архива `.7z` без распаковки: проверка структуры Firefox-профиля, безопасных путей и целостности через `7z t`.
- Восстановление архива `.7z` в новую отдельную папку: проверка пути к исходному архиву и родительскому каталогу на reparse points, проверка списка путей и целостности, распаковка во временный каталог и публикация только после проверки файлов профиля.
- Сохранение старых архивов при неудачном резервировании.
- Отказ от резервирования, если в дереве профиля или любом компоненте пути к профилю/каталогу назначения обнаружены символические ссылки или junction; состав и размер профиля повторно проверяются перед публикацией.
- Отказ от резервирования каталогов без корневого `places.sqlite` или `logins.json`.
- Отказ от резервирования, если обнаружен запущенный процесс Firefox; приложение не закрывает браузер принудительно.
- Защита от параллельного резервирования в одну папку.
- Фоновая задача Планировщика Windows с триггером **при входе текущего пользователя**, типом входа `InteractiveToken` и уровнем прав `LeastPrivilege`. Имя задачи включает SID пользователя, поэтому отдельные учётные записи Windows не перезаписывают друг другу настройки. Фоновый процесс работает с правами того же пользователя, который выбрал каталог назначения; SYSTEM для резервирования не используется.
- Журнал `backup_log.txt` и ротация архивов старше 30 дней после успешного резервирования; удаляются только файлы, соответствующие шаблону имени, создаваемому самим приложением.

## Важные ограничения

1. **Firefox должен быть закрыт.** Программа проверяет наличие процессов Firefox и отменяет резервирование, если обнаруживает хотя бы один. Она не завершает браузер автоматически. Проверка повторяется после создания и тестирования архива, но не блокирует запуск браузера атомарно.
2. **Передача пароля.** Значение пароля не попадает в командную строку процесса 7-Zip: приложение передаёт его через перенаправленный стандартный ввод UTF-8. Это снижает риск раскрытия через список аргументов процессов, но не защищает от локального администратора, отладчика или вредоносной программы с достаточными правами.
3. **Пустой пароль означает незашифрованный архив.** Это допустимая настройка, а не ошибка.
4. **DPAPI CurrentUser привязан к учётной записи Windows.** Сохранённый пароль не предназначен для расшифровки из другой учётной записи. ACL конфигурации дополнительно ограничивает доступ текущим пользователем, LocalSystem и локальными Administrators; это не защищает от администратора, способного изменить ACL или получить доступ к профилю пользователя.
5. **Фоновая задача работает только после входа пользователя.** Она не запускается до входа в Windows и не работает с привилегиями SYSTEM. Доступ к каталогу резервных копий определяется правами текущей учётной записи. Сетевые и съёмные хранилища всё ещё требуют проверки на целевой системе.
6. **Переход со старой SYSTEM-версии требует одного ручного действия.** Если обнаружена задача старой версии, приложение остановит настройку и покажет команду для удаления старой задачи из повышенного Терминала. После удаления старой задачи нужно запустить новую версию и настроить резервирование заново; сохранённый пароль потребуется ввести повторно. Старые архивы и прежняя конфигурация автоматически не удаляются.
7. **Восстановление через интерфейс реализовано, но ещё не подтверждено на настоящем профиле Firefox.** Программа распаковывает архив только в новую отдельную папку и не перезаписывает текущий профиль. Проверка `7z t` и smoke-восстановление синтетических файлов не заменяют реальное восстановление и запуск профиля Firefox.
8. **Символические ссылки и junction не поддерживаются в профиле и компонентах путей к профилю/каталогу назначения.** Резервирование завершается безопасным отказом. Каталог без корневого `places.sqlite` или `logins.json` также не принимается за профиль Firefox.
9. **Ротация не сохраняет минимальное число копий.** После успешного резервирования могут удаляться архивы выбранного профиля старше 30 дней. Храните независимую копию на другом носителе.

## Системные требования

- Windows с .NET Framework 4.x и Windows PowerShell с модулем ScheduledTasks.
- Установленный 7-Zip с `7z.exe` в одном из стандартных каталогов Program Files.
- Для обычной настройки и создания пользовательской задачи права администратора не требуются.
- Исполняемый файл должен оставаться по постоянному пути после регистрации задачи. Рекомендуется использовать отдельную стабильную папку, доступную текущей учётной записи.
- Поддерживаемые версии Windows и .NET должны быть подтверждены испытаниями конкретного релиза.

## Сборка

1. Скачайте `compile.bat` и `compiler_code.cs` из одной и той же ревизии в один доступный для записи каталог.
2. Запустите `compile.bat`. Для компиляции и обычного запуска приложения права администратора не требуются.
3. Убедитесь, что компилятор завершился без ошибки и создан `Firefox_Backup_Manager.exe`.
4. SHA-256, выводимый скриптом, является контрольным отпечатком файла. Сам по себе он не удостоверяет автора или подлинность сборки.

## Автоматическая проверка

GitHub Actions собирает приложение на Windows runner, устанавливает 7-Zip, проверяет создание, отдельную проверку и восстановление синтетических архивов, неверный пароль, повреждённый архив, опасные пути, безопасную очистку junction, DACL конфигурации, DPAPI CurrentUser, отказ при работающем `firefox.exe` и фактическую регистрацию, запуск и удаление пользовательской задачи с `InteractiveToken` и `LeastPrivilege`. Workflow запускается при push в `development` и при pull request в `main` или `development`. Результат конкретного запуска следует проверять на странице [GitHub Actions](https://github.com/lebvmikhail/firefox-backup-manager/actions/workflows/windows-build.yml).

Smoke-тест использует синтетический набор файлов, включая заглушки `places.sqlite` и `logins.json`. Он подтверждает работу архивного движка и сценария распаковки, но не совместимость с настоящим профилем, корректность базы SQLite или успешный запуск восстановленного Firefox.
